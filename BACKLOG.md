## Standing notes

- The AEMET key is shared and never committed (plan section 9). It is stored per-device via `SecretStore` (Keystore-backed `EncryptedSharedPreferences`), entered by the user, never in the binary or repo.
- `androidx.security:security-crypto` is deprecated by Google; we deliberately stay on 1.1.0-alpha06 (its terminal release, so "alpha" means "last", not "churning") because it is the documented, single-secret path and swapping in a plain Keystore-AES wrapper later touches only `SecretStore.kt`.
- The 24h/12h clock lives as a mutable flag on `:core`'s `AuraTime` (matching the Swift static), kept in step with the `Settings` DataStore boolean by `HoyViewModel` — the one place `:app` writes it. Compose reads it synchronously; `:core` stays android-free.
- Device location resolves to a `:core` `Coordinate` only; turning that into an AEMET INE needs the `SpainCities` nearest-municipality table (not yet ported), so `LocationProvider` is built and spec-complete but not yet driving the forecast.
- Location uses the platform AOSP `LocationManager` (via `LocationManagerCompat.getCurrentLocation`), never Google Play Services. This keeps Aura working on GMS-less devices and behaving the same on every OEM as on the emulator. `:app` acquires location and hands `:core` a plain `Coordinate`; `:core` stays free of any `android.*` or `com.google.*` import. Full spec in the local `specs/location.md`.
- Test-device plan: a Pixel is the clean development reference; the real OEM variety (Samsung, Xiaomi) comes from Samsung Remote Test Lab and Firebase Test Lab rather than more hardware. Watch for OEM background-killing (WorkManager for any refresh, never a bare service).
- The version stack is pinned deliberately. Read `CLAUDE.md` before bumping anything.
- MITECO's air-quality host has an incomplete TLS chain. The fix is a scoped Network Security Config trust-anchor for that domain only, not a global bypass (plan sections 5 and 10).
