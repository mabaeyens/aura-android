# Backlog

What is next on aura-android, roughly in order. This tracks the phased roadmap in the porting plan (`aura-apps/specs/android-port.md`, section 11).

## Done

- 2026-08-25: Ported the two Canvas arc cards, Sol and Luna (`ui/cards/SunArcCard.kt`, `MoonArcCard.kt`), over a shared `ui/cards/ArcCard.kt`. `AuraSunArcCard` is the shallow horizon-to-horizon arc with the sun riding at its live position, orto/ocaso beneath (each with its civil-twilight footnote), the daylight-remaining readout, and the solar-noon + daylight-length lines (the length line carries the day-over-day delta from a second `SolarTimes.compute` of yesterday). `AuraMoonArcCard` is the night twin tracing the moon's own salida/puesta from `:core`'s `LunarTimes`, the disc wearing tonight's true phase via the shared `drawPhasedMoon`, and counting down to the moon's next event; the ~650-evaluation `LunarTimes` scan is `remember`ed so it solves once, not per recomposition. `ArcCard.kt` holds the shared `sin(π·t)` polyline (`arcPath`, matching `AuraSunPath`'s altitude curve so the drawn arc and the sky's path agree), the horizon+faint+travelled track drawer, the disc position and glow, and the pure `hhmm`/`compact` helpers. Both cards degrade to "Horario … no disponible" without times/coordinates. Divergences noted in code: no per-shape blur in a `Canvas` at minSdk 26, so the sun/moon glow is a radial-gradient falloff rather than a blurred disc; Material core has no `sunrise.fill`/`sunset.fill` weather glyph, so orto/ocaso and salida/puesta are marked with an up/down chevron in the warm/cool tint (rising vs setting); 24h `HH:mm` es-ES until `AuraTime`; no `.minimumScaleFactor` shrink-to-fit. Added Madrid coordinates to the sample snapshot and both cards to the `@Preview` gallery. Deferred: the tap-through detail sheets (`AuraSolarSheet`/`AuraMoonSheet`) the Swift cards open, which land with the sheet suite; the VoiceOver `accessibilityValue` collapse (Compose `semantics`), to revisit with the a11y pass.

## Standing notes

- The AEMET key is shared and never committed (plan section 9).
- Location uses the platform AOSP `LocationManager` (via `LocationManagerCompat.getCurrentLocation`), never Google Play Services. This keeps Aura working on GMS-less devices and behaving the same on every OEM as on the emulator. `:app` acquires location and hands `:core` a plain `Coordinate`; `:core` stays free of any `android.*` or `com.google.*` import. Full spec in the local `specs/location.md`.
- Test-device plan: a Pixel is the clean development reference; the real OEM variety (Samsung, Xiaomi) comes from Samsung Remote Test Lab and Firebase Test Lab rather than more hardware. Watch for OEM background-killing (WorkManager for any refresh, never a bare service).
- The version stack is pinned deliberately. Read `CLAUDE.md` before bumping anything.
- MITECO's air-quality host has an incomplete TLS chain. The fix is a scoped Network Security Config trust-anchor for that domain only, not a global bypass (plan sections 5 and 10).
